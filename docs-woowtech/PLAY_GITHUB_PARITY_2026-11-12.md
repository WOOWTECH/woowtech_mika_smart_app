# 渥屋助理 GitHub 版／商店版功能對照（2026-11-12）

## 共用核心對齊進度

GitHub 版候選 `woow.10` 已移入商店版的技能結果評分修正，並讓外部 MCP 一般工具、合成資源及提示工具遵守允許清單。兩版新增呼叫前重新檢查目前設定；執行中撤銷後的下一次呼叫會被拒絕，已開始的呼叫不會追溯取消。舊設定 `allowedTools=null` 仍表示不限制。GitHub 版保留既有 `read_file` 長結果分段讀取，商店版保留專用結果讀取器。下文是對齊前 `woow.9`／`play.1` 的基準觀察，不應當作候選版的實機驗收結果。

## 比對基準與界線

- POCO 25078PC3EG、Android 15；已安裝 `io.woowtech.agent` `0.1.37-woow.9` 與 `io.woowtech.assistant` `0.1.37-play.1`。兩個套件可共存，資料和模型設定各自獨立。
- 原版程式基準為 GitHub `origin/main` `05bce637`（`woowtechRevision=9`）；商店版為本分支 `b959dc36`。手機版本號符合，但尚未以 APK 雜湊證明原版手機安裝檔恰由該 commit 建置。
- 商店版真實模型、HA MCP、記憶、技能、語音和附件驗收依 `PLAY_POCO_ACCEPTANCE_2026-11-12.md`。本輪另直接操作 POCO 上的原版介面、瀏覽器及一則測試對話。測試對話已個別刪除，未更改原版模型設定。
- 使用者提供的 Omnigent 對話連結需要登入；未取得對話內容。本表只對照可核實的程式、手機狀態和既有驗收紀錄，不能視為已核對該對話逐項要求。

## 設計上刻意不同的能力

GitHub 版保留手機操控、定時任務、電腦／中繼連接、遠端喚醒解鎖、手機提供 MCP 服務及 App 內 APK 更新；商店版移除這些入口與執行能力，以符合商店版已確定的產品範圍。這些不是「共同功能」的退化。商店版另有 AI 回覆檢舉入口，原版目前沒有。

## 後續處置建議

1. 把技能評分修正移入共同核心並部署 GitHub 版；用相同測試技能驗證「`skill_read` 成功 → `done` → 技能仍啟用」。
2. 把 MCP 合成工具的允許清單修正移入共同核心；以具有 resources／prompts 的測試伺服器驗證清單外工具不會出現。
3. 先驗證 GitHub 版既有沙箱 `read_file` 能否讀取同一對話的 MCP 長結果；再評估是否需要共用專用讀取工具，並維持商店版只讀本對話結果檔的限制。
4. 原版先處理 `WOOW` 模型的限流或改用同一可用模型，然後再做同條件的對話、記憶、技能與 HA MCP 實機對照。這是建立端到端等價結論的必要條件。
