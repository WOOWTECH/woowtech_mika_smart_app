- 安裝版本顯示 0.1.37-woow.4 / 3804，實際為本機正式簽章語音修正版，來源 8f61ffb3。APK SHA-256：169407a72c1e5ed22e7218a70b4dccb90cc490e36ff0dc1bf3582c131f8e7d2c。不是 GitHub 原公開包。
- 經 App 已授權的 USB 任務 API 建立真實對話，使用目前 App 的模型與工具。手機操作由 App 實際執行，另以 ADB 核對系統讀值；沒有用 mock 代替模型或工具。
- 任務 done 不是通過判定：另檢查答案、狀態收據、部分執行過程 UI、下載檔案內容。CSV/JSON/UTF-8/ZIP/HTML 均讀回；兩份下載的 Python 在檢閱內容後獨立執行。
- 操作過程的快照未涵蓋每一步。計算機／Chrome 依 App 操作紀錄及答案判定，未另保存每個結果畫面的獨立截圖；不可等同每案都有第二套視覺驗證。
- 沒有查閱一般私人對話、付款或對外傳訊。合成測試資料與對話留存，測試記憶已以單筆刪除清理。

## 問題與後續修正依據

### QA50-41：自動刪除記憶失敗（高優先）

新增與跨對話檢索成功，但要求刪除時，模型先嘗試檔案命令，之後開啟 **com.wangzan101.mika**。執行過程第 4 步明確顯示這個套件；後續在 Mika 的空記憶頁搜尋，無法刪除存在於渥屋助理的資料。原任務 85.39 秒後回報 failed/gaveup，沒有虛稱刪除，也沒有使用全部清除。UI 顯示 15 次模型往返、36.5 萬 Token。

人工開啟 io.woowtech.agent 的「記憶與技能」可看見 QA50測試專案的代號是鳶尾713。以該列的刪除按鈕清理後，UI 顯示沒有記憶；同一測試對話再次執行 memory_search 亦查無結果。這是清理成功，原自動流程仍列失敗。

程式檢查：MemoryTools.kt 目前只有搜尋／新增工具；MemoryViewModel 支援單筆刪除。品牌提示雖已說明另一個 Mika App 是別人，任務仍選錯套件。建議將目前執行套件身分納入任務上下文，並評估直接提供具明確範圍與確認語意的記憶刪除能力，避免靠操作其他 App 的設定頁處理自身資料。這些產品修正尚未實作、安裝或發布。

測試限制：測試人員在此案執行期間曾開啟其他已完成對話的過程頁。這可能干擾操作耗時；不能把每個 UI 問題都歸因於產品。但紀錄明確記載模型開啟 Mika，且正確套件內確有該筆資料，足以確認套件選擇錯誤。

### QA50-38：結果正確，恢復效率偏差（部分通過）

第一次啟動 com.android.settings 失敗，當時停留 com.miui.securitycenter。隨後連續三組「看螢幕／讀取介面元素」，第 8 步已有守衛提醒，之後才重新開啟設定成功並搜尋一次不存在的名稱。最後如實回答找不到，沒有假稱啟用。總耗時 83.70 秒，13 次模型往返，UI 顯示 28.4 萬 Token。

因此不能說完全沒有無進展守衛，也不能宣稱已重現 111M Token 問題。可確認的優化方向是啟動失敗後更早利用目標套件／實際前景套件差異恢復，減少相同畫面的重複讀取。上述 Token 為 App 顯示用量，未拆分快取與費率，不是費用結論。
