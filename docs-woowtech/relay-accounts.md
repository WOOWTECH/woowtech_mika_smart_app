# 個人帳號中繼連線

App 依 2026-11-10「App 整合契約 v1」取得配對所屬通道。不在手機輸入 tenant，不從 deviceToken 字串推算帳號，也不更動網站端。

## 操作與相容性

- 新配對先加密保存 deviceToken，再以它呼叫 GET `/device/info`。配對不會自動開啟遠端存取或喚醒權限。
- 既有配對在開啟遠端設定頁時查詢；無須解除配對。可手動更新，不做輪詢。
- 設定頁分別顯示閘道、帳號通道、電腦端網址。查詢成功只證明取得連線設定；CLI/MCP 是否能連線必須由電腦端另外確認。
- 「複製 MCP 位址／設定」使用經驗證的 mcpUrl；設定中的 Authorization 仍使用手機 MCP 存取權杖。deviceToken 不進剪貼簿或電腦設定。
- CLI 顯示 apiBaseUrl。此版本附帶的 `tools/mika/scripts/mika_cli.py` 支援 `/r/<22字元通道>/api/v1` 或同一個人前綴。網站另提供 `/downloads/woow-relay-cli.py`。
- 一支手機保留一份目前配對；切換帳號先解除配對，再輸入目標帳號網站產生的配對碼。這次不是同時保存多個帳號或多條 WebSocket。
- `/pair` 舊格式及 WebSocket 根 `/device`、`mika-relay.v2` 保持不變。

## 驗證及失敗處理

schemaVersion 必須為 1，協定必須為 mika-relay.v2。網址與 HTTPS 閘道同 origin（含 port），不得有帳密、query、fragment。gatewayUrl 必須為根路徑；MCP 只接受 `/mcp` 或 `/r/[A-Za-z0-9_-]{22}/mcp`，API 必須同前綴 `/api/v1`。允許未識別的未來 JSON 欄位。端點與配對憑證存在同一份加密資料內；換配對或解除時清除。舊請求的回應不能覆寫另一個配對。

- 401：清除可用端點，提示配對失效；不自動重新配對。
- 403、405、無效格式或不安全網址：停止使用端點並顯示設定異常。
- 404：保留配對，明示不支援取得網址，使用管理網站地址；不自動退回根 MCP。
- 429：同一配對至少等待 60 秒才再次查詢（程序內節流）。
- 網路失敗／5xx：保留已驗證地址並顯示更新失敗，可手動重試。每次查詢總時限 20 秒，不追隨重新導向。

## 測試範圍

協定測試使用本機 HTTP 測試伺服器；產品閘道仍要求 HTTPS。覆蓋舊配對格式、新配對後查詢、既有配對升級、未知欄位、同 origin／同通道驗證、HTTP 錯誤、逾時與重新導向不洩漏憑證。加密設定測試覆蓋切換帳號的延遲回應、權限變更、解除配對、離線恢復、MCP 設定權杖。CLI 子程序測試實際檢查兩個通道的 discovery 與 task 路徑（僅本機合成任務）。Compose 裝置測試覆蓋複製按鈕、網址顯示、未驗證／撤銷狀態及解除配對確認。

上述不等同正式網站兩個真人帳號的端到端驗收，也不代表已在 Pixel 上完成升級。不得據此宣稱遠端任務或喚醒已實測通過。
