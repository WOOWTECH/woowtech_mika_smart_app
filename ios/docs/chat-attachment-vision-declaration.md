# Image capability declaration for the selected model

Android exposes a user-controlled image capability for a provider and model (`app/src/main/java/com/wangzan101/mika/settings/ProviderStore.kt`, `ModelOptions.kt`, and `ui/ModelsScreen.kt`). Its provider catalog, separate vision role and multiple-model selection do not exist in this iOS candidate. Here the current single saved HTTPS endpoint and model have an explicit three-state user declaration: unknown, supported or unsupported. It is not established by a model name or the text-only connection test and does not prove the service will accept an image.

Existing saved records without a declaration load as unknown. The declaration is retained only while the exact saved endpoint, model and credential account remain the same; changing any one resets it to unknown, including switching away and back. An in-app settings revision prevents a stale confirmation dialog from overwriting a newer saved selection. The dialog names the saved endpoint and model, is unavailable while unsaved model fields differ, and changes no key. Endpoint and model may themselves contain personal information; they must not be logged.

The attachment review uses the saved declaration and still requires explicit confirmation of the exact one-shot destination, question and additional data. Changing the declaration revokes the review. Unknown and unsupported images remain blocked with distinct errors, and the session rechecks the saved settings before preparing the review and immediately before invoking the client. The declaration and attachment confirmation are separate decisions. The existing text-only path and existing attachment size and full-image-decoding checks remain in place. MCP and memory-enabled attachment requests are still unavailable; this is not complete Android feature parity.

The isolated Swift session suite uses synthetic data, isolated preferences, credentials and an in-process model client. It checks old-record migration, all three states, stale and away-and-back settings, endpoint-path and key changes, revocation in the preflight suspension, and actual serialized synthetic PNG requests. The persisted settings store is not a transactional multi-process compare-and-swap; the request is bound to the reviewed endpoint and model, and changed persisted settings are checked at the last synchronous client boundary, but this does not claim an OS-wide lock against a writer that changes settings immediately afterward.

The simulator UI tests are candidates only: they need Xcode, a disposable iOS simulator and the existing Debug-only isolated fixture. They do not test a real model provider or a physical device. This combined candidate includes the separate attachment replacement/stream-lease fix as its preceding commit; both changes still require independent review before adoption.
