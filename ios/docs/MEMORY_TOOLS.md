# 對話的記憶工具

2026-11-14 起依 Play 版調整：記憶工具不再顯示核對畫面，通過原話與目標檢查後直接儲存，聊天保留儲存紀錄與撤銷卡片。模型自己的修改或刪除、以及回覆中使用者對學習資料的變更，都不再中止這次回覆。以下為先前紀錄。

行為依據是 Mika `0c172724f3f0c96f7345262588072f6e95db1138` 的 `general/MemoryTools.kt`，不是依品牌或提示詞推測等效。這版接入一般聊天與 MCP 對話；本機學習操作和遠端 MCP 工具分開派送，不把本機工具加入伺服器的目錄。

| 工具 | 實際行為 |
|---|---|
| `memory_search` | 1–100 UTF-16 單位的查詢，只搜尋現用記憶，最多八筆；結果附穩定 ID，最新搜尋取代舊候選集合。 |
| `memory_save` | 只依本輪使用者原話提出 fact、preference 或 procedure；內容最多 200 單位、引用最多 1,000、關鍵字最多八個且各 30。 |
| `memory_edit` | 更新或刪除必須使用本輪實際搜尋結果中的 ID；多筆結果時引用需明確指向該 ID。不能憑舊對話、網頁或模型自己生成的內容授權。 |

「使用記憶」關閉時停用這些工具；「自動記住」關閉不阻止使用者明確要求的記憶修改。原話來源、重複 JSON 欄位、敏感內容、否定語意、無依據的具體值、過期 revision 或 generation 都會被檢查。語意判斷有邊界，因此 App 在每次寫入前展示完整引用、原內容、新內容、類型及關鍵字，須經使用者核准。

核准後先修改副本，再以既有 AES-GCM 檔案原子保存；儲存成功才更新畫面與工具 receipt。拒絕、取消、過期或寫入失敗不能發布成功。保存後模型回覆失敗仍保留修改紀錄，不自動重送寫入。程序類記憶先列為待確認，另行批准才啟用；更新程序會重新進入待確認。

對話中的記憶卡片支援撤銷；刪除卡片沒有現存記憶 ID，因此以實際 undo token 的可用性判定是否保留。切換偏好不會清掉仍能撤銷的刪除卡。Undo 仍受原有 stale、重複內容、容量與 50 筆程序內紀錄限制，重啟後不保留 undo token。這不是模型可自行呼叫的 `memory_undo` 工具。

一般聊天的個人檔案與普通記憶共用每輪一項修改、一次搜尋、三次前景模型呼叫（一般聊天沒有整體時間上限，2026-11-14 起同 Play 版）；最多一次格式修正也佔用相同呼叫額度。成功回答後的自動記憶整理是另一次背景請求。新整理不得覆蓋剛建立且仍有效的工具卡片；同一記憶有較新變更時才以新卡片為準。

與原版仍有明確差異：iOS 每次寫入增加原生審閱；僅接受本輪原話，尚未移植 Mika 針對上一輪明確確認的保存例外；單輪操作與模型額度較小。獨立技能／瀏覽器執行器及所有原版工具的整合仍需另外驗收。

MCP 對話維持 12 次模型決策、六次遠端操作、180 秒共同期限；本機搜尋與修改也計入這 12 次模型決策，另限一次搜尋、一次修改。個人檔案與普通記憶共用修改額度，修改後不再搜尋本機記憶，並保留至少一次模型呼叫用於交付。遠端步驟仍需各自核准，不因已有本機核准而放行。同名遠端工具也只會呼叫遠端伺服器，不會轉成本機操作。

MCP 模式的本機修改使用相同的原話、revision、generation、主開關及原子保存檢查；等待使用者審閱後，先重查整輪期限與取消狀態，接著不中斷地同步保存。斷線、拒絕、取消、清除資料或並行修改都不能讓舊提案落盤。若先保存個人檔案、再拒絕遠端呼叫，已保存 receipt 和內容保留，草稿也保留。遠端結果中的「請記住」不能替代本輪使用者原話。新增混合流程的本機 App 檢查通過 Debug 573、Release 492；其中新 MCP 群組 97 項與實際 fixture 客戶端八項，另待原生 UI／真實服務驗收。[精確來源與執行紀錄](evidence/mcp-learning-app-local.json)。

本機核心通過 245 項記憶工具斷言（十組）、97 項既有 profile 工具斷言及 91 項記憶核心回歸。實際 App 邏輯／隔離加密檔案檢查通過 Debug 468、Release 395；先重現刪除卡片因偏好變更而消失，再以同一案例驗證修正。實際 fixture 客戶端另外驗證搜尋結果中的真實 ID，沒有直接修改 App 資料。

本機真實模型透過 production `HTTPChatModelClient` 完成 29 次呼叫：個人檔案新增、普通記憶新增、搜尋後刪除與撤銷、程序待確認後批准、20 輪完整對話，以及超大輸入拒絕且不呼叫模型。保存均以真正加密檔案重開驗證；只有合成測試內容，審閱由測試驅動核准。這是 macOS 上的 App 邏輯測試，**不是 iOS UI、真人審閱或真機驗收**。證據固定於當時來源 hash，早於後續撤銷卡修正；不把不同來源的成功當成最新版本全面通過。

六個 fixture UI 案例及一個真實模型 UI 案例已加入 CI，涵蓋核准／拒絕、搜尋後更新／刪除、撤銷、待確認做法批准／拒絕與重啟讀回。結果按來源版本記於[驗證紀錄](VERIFICATION.md)。
