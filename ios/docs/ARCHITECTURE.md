# Architecture decision record — iOS assistant

## Product boundary

The target scope is model conversations, memory, file work, controlled MCP connections, declarative skills, WebKit browsing, notifications, language and appearance. Not all are implemented; see the verification log. It never controls other iPhone apps, uses Accessibility to automate the device, records the screen, runs ADB, or executes arbitrary local programs.

## Modules

`AssistantContracts` owns Codable messages shared with the future gateway. `AssistantDomain` owns run state without UI dependencies. `AssistantBrowser` owns URL policy, research/website/route state, DOM approval validation and a fixed isolated-world WebKit adapter. `AssistantModels` owns JSON/SSE networking; `AssistantMCP` owns Streamable HTTP and a bounded model conversation runner. Memory, Skills and encrypted persistence have separate modules. The app target owns SwiftUI, foreground sessions, settings and device-only Keychain adapters.

## Browser modes

`local_webkit` is the only default mode. Its cookies and login data remain in the app's WebKit data store. `remote_browser` is a later, opt-in server capability for CDP-grade automation; it never receives local cookies, passwords, OTPs or Passkeys automatically.

## Implemented execution boundaries

Like the Play build (2026-11-14), a saved MCP server needs no manual connect: a chat that has MCP turned on connects to it when the request starts (`MCPSession.chatConnection()`), and the MCP page can still connect to show the catalog. Every tool is allowed until the user turns one off; the choice is kept in the server's Keychain service like Play's allowlist (nil = all). "All" means every tool the conversation runner accepts, in server order, within its 64-tool and 128 KiB catalog limits, so one malformed or oversized tool cannot stop every MCP chat. An optional access token is sent as `Authorization: Bearer <token>` on every request (redirects are refused, so it only reaches the saved endpoint) and is stored next to the endpoint in the same Keychain service; saving a different endpoint drops the old token and tool choice. In the background iOS stops the network work: the connection closes, the catalog and choice stay, and it reconnects when the app is active again; a brief interruption (Notification Center, an alert) keeps it. A call that fails on the open connection (an expired server session, a restart) is not retried, but the next chat connects again. The per-chat MCP switch stays for 1.0 because an MCP chat cannot also use web tasks or skill tools yet (1.1). Like the Play build, up to 30 resources the server lists are offered read-only without a picker; server prompts are not offered. The runner receives that immutable catalog and the same connection; it accepts only strict JSON commands and runs the exact arguments or resource URI of a selected tool or offered resource. Like the Play build (since 2026-11-13) there is no per-call approval: the tool selection is the limit, and each call and result is listed in the chat's results view. Connection/selection changes, going to the background, cancellation and the 180-second deadline invalidate outstanding work. The runner permits at most 12 model requests and 6 executions, rejects duplicate operations, and does not retry side effects. Attempt counts are distinct from received results. Tool errors stop execution while preserving received results for review.

Browser research remains read-only. The separate interaction entry point observes stable document/node IDs, asks the model for one action, and waits for a native review. A one-use grant expires after 60 seconds. Before dispatch, fixed JavaScript checks document/snapshot identity, the actual node reference and its captured attributes/form values. All values cross the WebKit argument bridge; no model-supplied JavaScript runs. DOM events are synthetic; dispatch is not proof of a completed website task. Interaction traces are not automatically treated as read-only routes or successful skill-learning evidence.

Chat turns follow the Play build (since 2026-11-14). The question enters the transcript and the input bar empties when it is sent; a working row (spinner, 正在處理, elapsed time) stands in until the reply streams. A turn ends as an answer, as 沒有完成 with its reason, or as 已停止。; all three are saved with the conversation (archive v6, `ArchivedConversationTurn.outcome`), and only answered turns go back to the model as history. Ordinary chat has no fixed time limit (MCP runs keep their 180-second host deadline). A conversation is not tied to the model it was saved with: changing the main model keeps the open conversation, any saved conversation opens from the drawer and continues on the current main model, and its row keeps the model of its latest turn. One encrypted archive file holds up to 200 conversations of up to 1000 turns and 8 MiB; when a save would pass a bound, the oldest unpinned conversations give way (their attachment files with them) instead of the save failing.

The bundled skill catalog stays a pinned, hash-checked archive of the original documents and scripts. Like the Play build (since 2026-11-14) the App has no catalog page, skill-writing pages or PDF runtime; the archive supplies the upstream LICENSE and NOTICE for Settings › About. Remote gateway, full original-skill tool registration, provider-native function-call streaming and full browser parity remain unfinished.

- Credentials belong in Keychain, never SwiftData, logs or chat content.
- iOS keeps Keychain items after the App is deleted. `FreshInstallKeychainReset` removes the production services on the first launch of a fresh install (no marker, App defaults or App files) and keeps them on an upgrade, whose encrypted files need their keys. A new production Keychain service must join its list.
- MCP is an outbound client. Server annotations and descriptions never authorize calls; the remote server validates its input schema. A manual Bearer access token is supported; OAuth, stdio, legacy SSE and several servers remain unsupported (1.1).
- Skills are reviewed text context, not local executable programs. Optional remote computation must be distinguished from iOS capabilities.
- Approval is bound to the current immutable operation and run. Neither a model answer nor a saved JSON boolean is an approval credential.


## Browser workspace and files

BrowserWorkspace owns one persistent WebKit profile and a separate BrowserSession/WKWebView per live tab. Metadata is encrypted with a dedicated device Keychain key; known callback/secret URLs are excluded. Manual HTTPS navigation accepts login/query URLs while model research retains its existing public-page restrictions. Switching/closing tabs revokes pending proposals. Website-record removal first quiesces every old document, then removes the selected records; history/bookmarks and learning data have separate deletion controls.

Like the Play build (since 2026-11-14) the browser refuses downloads with 「瀏覽器裡暫時不能下載檔案。」. Native WebKit file inputs use the system chooser on iOS 17. DEBUG upload fixtures permit only an exact loopback origin/path; the loopback ATS exception is in the Debug plist only. Release builds have no fixture server or ATS exception.
