# Non-Live iOS CI full regression

The normal iOS workflow runs the exact `ui_inventory` set on iPhone SE (3rd generation) and iPhone 16 Pro Max with iOS 18.5/Xcode 16.4, and iPhone 17 with iOS 26.2/Xcode 26.2. The iPad-only read-only navigation method runs once on iPad (A16)/iOS 26.2. Live model/MCP tests remain in their explicitly triggered workflows.

There are **two** `build-for-testing` jobs, one per Xcode. Their portable `.xctestproducts` bundles carry source, Xcode-version, and ZIP checksums. Each selected device cohort downloads the matching bundle and uses only `test-without-building`. The 15 UI shards and seven core test targets remain separate XCTest invocations/result bundles; seven balanced cohorts per iPhone plus one iPad job make **22** test-only jobs and **49** shard/core invocations. `max-parallel: 9` bounds simultaneous macOS runners. Each cohort has a 55-minute execution budget, each native invocation 30 minutes, and no retry. The focused manual `test_scope` path stays available; its `all` selection now uses this complete plan.

The plan is generated from current source before tests. Every iPhone must execute every eligible non-Live method exactly once, all seven core targets once, and the iPad method on iPad once. UI and core receipt verification requires a completed `xcresult` summary, an exact passing XCTest log, zero skips/failures/expected failures, and zero `xcodebuild` exit status. The aggregate gate compares **all 49** receipts against the same source commit and inventory hash, and requires preflight, both builds, and all test jobs to succeed. A missing result, incomplete bundle, timeout, duplicate, or changed selection remains red. Raw `.xcresult`, logs, summary, and bounded fixture diagnostics are retained per cohort; the gate downloads only small receipts.

This avoids a single 55-minute test step that can be killed before Xcode finalizes its result bundle. It does not assert that the current App passes native tests; existing assertion failures remain visible in their own shard artifacts. Local script/actionlint checks validate the plan and YAML, while portable bundle layout, WebKit overlay lookup on iOS 18.5, and actual Simulator execution require a GitHub macOS runner. After merging, one complete CI run is needed before treating the new gate as proven native execution. If branch protection names the old `build-and-test` job, update it to require `full-regression-gate` after that run.
