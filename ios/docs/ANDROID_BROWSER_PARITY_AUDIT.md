### Android 網頁工具完整名稱核對

在 [WebGroup](../../core/src/main/kotlin/com/wangzan101/mika/core/cap/web/WebTool.kt#L21) 與 [ScreenTool 清單](../../core/src/main/kotlin/com/wangzan101/mika/core/uistate/tools/ScreenTool.kt#L35) 可靜態看到以下 26 個名稱；這是來源中的**註冊候選**，是否對某次任務可用仍由 web port、permissions、DevTools 與環境決定，不是 APK runtime 證據：

- 共用畫面族：`web_observe`、`web_list_elements`、`web_screenshot`、`web_describe`、`web_find_visually`、`web_tap`、`web_scroll`、`web_swipe`、`web_type_text`、`web_clear_text`、`web_back`、`web_press_key`、`web_diagnose`。

不能把 iOS `browser_inspect`、`browser_open_link`、`browser_find`、人工分頁、手動下載或單次核准操作，按名稱視為上述工具的逐一實作。也不建議只按名稱移植；先定義使用者批准、資料邊界、取消和可觀測成功條件。

## LAN 候選與驗收順序

1. **現況**：`272c702` 的 [第一階段 LAN 文件](BROWSER_MANUAL_LAN_POLICY.md) 明示 policy 尚未接線；`6dbd017` 是另一條未合入候選，具手動核准與 tab/revoke 邏輯。候選有本機 macOS 真實 WebKit／loopback 合成測試；這不是 iOS 原生 SwiftUI、WebKit、ATS 或裝置實測。
2. **未完成**：在隔離的合成 loopback 服務上，對候選執行 iOS 模擬器及支援版本的實機測試，涵蓋不同 host／port、使用者取消、tab／關頁／背景撤銷、同源與跨源重導向、TLS 失敗、權限提示與 Release ATS。若要測私網，先使用由測試人員明確建立並隔離的合成服務；本次沒有連任何真實家用裝置。結果須記錄 OS、建置、網路狀態與精確提交。
3. **安全邊界**：候選依網址字面分類，不驗證 DNS 解析結果或防 DNS rebinding；WebKit 的腳本、圖片、frame 等子資源沒有連線層隔離。重導向政策也不保證目標請求未在回應判定前送出。ATS 例外是 app-wide，不能說成只限特定分頁或已核准 origin。
4. **下一批優先缺口**：頁內提問／選取文字與續聊、借頁／暫停、登入登記／popup、首頁常用站合併與圖示、一般載入 stop，以及 agent web 工具逐項能力和授權設計。以人工流程與真實合成服務回應作驗收，避免只測靜態按鈕。
