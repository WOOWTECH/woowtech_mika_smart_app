# Manual LAN browsing

A user may enter an explicit HTTP or HTTPS local URL in the browser address field. Bare localhost and literal IP addresses use HTTP; bare `.local`, `home.arpa` and `.localhost` names use HTTPS, including when a port is specified. Other single-label names require an explicit scheme, such as `http://router/`. The browser displays a localized confirmation before navigation, showing the origin without the path or query and describing the HTTP transport risk and other resources the page can load. Approval is bound to the entered address and the current visible WebKit page: editing the address, changing the page or starting navigation invalidates the pending request. Rejecting, switching or closing a tab also invalidates it. Approval is in memory and limited to the selected session and scheme/host/effective port; local URLs are not written to browser history or bookmarks. Closing the browser, switching tabs, closing a page, cancellation and data removal revoke access and retire the local WebView. A previous network request cannot be recalled.

The manual URL classifier accepts loopback, RFC 1918, IPv6 ULA, link-local literals, localhost, `.local`, `home.arpa` and single-label names. It rejects malformed authorities, credentials, unsupported IPv6 zone identifiers, trailing-dot hosts and other addresses described by the underlying policy. DNS names are classified by spelling, not resolved address; names can resolve unexpectedly or be rebound. Loopback refers to the device running the app. Research and interaction do not receive an observation from an authorized local document; the existing research, MCP, downloads, and shared URL policies are not widened. Local downloads remain unavailable.

While a local document is active the navigation delegates require the approved origin, including for redirects, and pop-up windows are disabled. **This is not a connection-level isolation boundary.** WebKit may send a redirect request before a response policy decision, and scripts, images, frames and other subresources can make requests outside the approved origin. A URL policy cannot prevent DNS rebinding or guarantee the server reached. The app does not change certificate trust or bypass invalid TLS certificates.

The Debug and Release plists have explicit `NSExceptionDomains` entries for IPv4 loopback/private/link-local ranges, `::1`, IPv6 ULA/link-local, `localhost`, `local` and `home.arpa`. These ATS exceptions are app-wide, not restricted to WebKit or to an individual approval; they can weaken transport requirements for other components contacting the listed destinations. They do not include global `NSAllowsArbitraryLoads` or `NSAllowsLocalNetworking`. `release_ios.py` accepts either the previous absent ATS dictionary or exactly these exceptions and checks the built product. Single-label names other than localhost and mapped IPv6 behavior need native platform verification; the UI does not guarantee a server can be reached. ATS CIDR and local-name behavior must be validated on supported iOS versions before release.

The exceptions permit HTTP for the listed destinations; by themselves they do not relax HTTPS trust evaluation, TLS version or forward-secrecy requirements. Apple says per-domain insecure HTTP exceptions require an App Store review justification. See [Apple's key documentation](https://developer.apple.com/documentation/bundleresources/information-property-list/nsexceptionallowsinsecurehttploads).

Apple documents that WKWebView traffic is exempt from the iOS Local Network privilege; the app confirmation is not an OS permission prompt. A future native networking or DNS implementation must separately account for local network permission. Relevant Apple references: <https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy>, <https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsexceptiondomains>.

Run `bash scripts/check_browser_manual_lan.sh` for pure policy tests and `python3 -B scripts/check_browser_site_modes_app.py` for actual macOS WebKit and synthetic loopback server checks, including an explicit approval, denied cross-origin navigation, server redirect and tab lifecycle. The fixture counts only loopback connections and uses no personal profile, real devices or credentials. An iOS hosted test is registered for the loopback flow. This Mac lacks an iOS SDK; macOS results and Swift syntax parsing do not establish iOS runtime behavior, ATS enforcement, SwiftUI typechecking or native XCTest success.
