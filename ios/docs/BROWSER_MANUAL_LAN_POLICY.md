# Manual LAN policy: first stage

This is an internal Swift policy and in-memory approval state, not a usable browser feature. It is not connected to address entry, WebKit, downloads, app settings or ATS. The existing manual browsing, research, MCP and release policies remain in force. No permission is persisted.

`BrowserManualLANAccess` starts disabled. Each instance holds one lock-protected authority; all references to that instance share pending requests and grants, and revocation through any reference affects every reference. Separate instances are independent sessions. A manual request invalidates any previous request or grant; only the exact outstanding request can be approved. A grant covers one URL origin: scheme, host and effective port. A proposed top-level navigation or redirect to a different origin is rejected by the state. Revocation removes pending and granted state. Calling this policy alone does not load a URL, and a previously returned decision does not cancel an already-started operation.

Candidates require explicit HTTP or HTTPS and a well-formed raw and parsed authority without credentials. They include canonical loopback, RFC 1918, IPv6 ULA, link-local literals, localhost, `.local`, `home.arpa` and single-label names. Invalid ports, noncanonical IPv4, scoped IPv6, unspecified, shared, multicast, reserved, deprecated IPv6 site-local and public literal/domain destinations are rejected. Hosts ending in a dot are rejected for both requests and navigation decisions until iOS WebKit origin behavior is verified. Names are classified by spelling only; single-label names and local-looking names can resolve unexpectedly. Loopback refers to the device running the app. DNS resolution, rebinding, actual routing, server trust and connection timing are not checked by this type.

This state does not intercept WebKit requests, redirect connections or subresources. The future integration must define its actual security boundary, user-facing authorization, ATS and trust behavior, navigation lifecycle and revocation, and verify those behaviors in iOS. In particular, a URL policy decision alone is not a network isolation guarantee.

Run the no-network Command Line Tools checks with `bash scripts/check_browser_manual_lan.sh`. The XCTest suite `BrowserManualLANAccessTests` is also included in the workspace test scope; native XCTest execution requires Xcode. Neither test is an iOS network or WebKit acceptance test.
